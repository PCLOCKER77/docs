# 1. Purpose

This document defines the known issues and limitations template for Digitize releases.

It ensures known issues are communicated from approved Release Management closure evidence without assigning defect acceptance or release approval ownership to Release Notes.

---

# 2. Scope

This template covers:

- Known issue summary.
- Limitation summary.
- Customer impact.
- Workaround.
- Affected users or tenants.
- Expected resolution status where approved.
- Support guidance.

---

# 3. Out of Scope

This template does not define defect acceptance, risk acceptance, release approval, rollout continuation, rollback decisions, or incident handling.

Those concerns are owned by Release Management, Testing, Operations, and Deployment.

---

# 4. Governing Standard

This document inherits `RN-00_Release_Notes_Standards.md`.

Known issues shall be based on approved Release Management closure evidence.

# 6. Communication Rules

Known issue communication shall:

- Use approved issue descriptions.
- Avoid exposing exploit paths or sensitive operational details.
- Avoid assigning blame.
- Clearly distinguish known issues from limitations.
- Include workaround only when approved.
- Avoid promising fix dates unless approved by Release Management and Product.

---

# 7. Acceptance Criteria

This template is acceptable when:

- Known issues are linked to Release Management closure evidence.
- Limitations are clearly separated from defects.
- Customer impact and workaround fields are present.
- Sensitive information is protected.
- Release Notes does not accept or reject defects.

---

# 8. Freeze Rule

This template shall remain `Design Draft` until `RN-00` is reviewed and known issue communication ownership is accepted.
